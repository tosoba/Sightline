# 22: Add shared framework + SwiftUI iosApp + first end-to-end slice

**Spec:** `.scratch/kmp-ios-migration/specs/module-architecture.md`, `.scratch/kmp-ios-migration/specs/navigation.md`

**What to build:** A `shared` XCFramework exports the shared pipeline through SKIE, and a SwiftUI `iosApp` fetches nearby places for a chosen category via the shared location -> photon -> data -> model pipeline and shows them in a list. This proves the full shared stack works on iOS.

## Comments

`shared` is a new iOS-only KMP module (`iosArm64`, `iosSimulatorArm64`) that applies Kotlin Multiplatform, Metro, and SKIE 0.10.16, and registers `XCFramework("Shared")`.
It exposes `api` dependencies on `core:common`, `core:model`, `core:data`, and `core:domain`; the framework exports `core:model` and `core:common` (the types the Swift facade returns) and builds a static `Shared.framework`.
`./gradlew :shared:assembleSharedXCFramework` writes `shared/build/XCFrameworks/debug/Shared.xcframework` and `.../release/Shared.xcframework` with `ios-arm64` and `ios-arm64-simulator` slices.

SKIE 0.10.16 is in `libs.versions.toml` and applied only to `shared` (it cannot apply to Android targets).
Suspend functions are exposed as Swift `async throws`, and Kotlin `Flow` properties are bridged to Swift `AsyncSequence` through SKIE's apinotes (`SharedSkieKotlinFlow` -> `SkieSwiftFlow`).
This is easy to misread: the raw `Shared.h` still declares `id<SharedKotlinx_coroutines_coreFlow>`; the conversion lives in `Shared.framework/Headers/Shared.apinotes`. The real proof is the Swift app compiling and running `for await location in shared.locationUpdates` and `for await state in shared.authorizationState`, which it does.

iOS dependency injection is Metro, same graph model as Android.
`shared/src/commonMain/.../IosAppGraph.kt` declares `@DependencyGraph(AppScope::class)` with `placesRepository`, `locationProvider`, and `userPreferencesRepository`, plus a factory that takes a `UserPreferencesDirectory`.
`core:data/src/iosMain/.../DataModule.kt` provides the DataStore (backed by `userPreferencesStorage`) and `UserPreferencesLocalRepository`; `UserPreferencesDirectory` lives in `core:data` commonMain.
The existing `core:common` iosMain `NetworkModule` (Darwin Ktor client) and `LocationModule` are picked up through `@ContributesTo(AppScope::class)`.
`SightlineShared.Companion.create()` resolves the Application Support directory, creates the graph with `createGraphFactory<IosAppGraph.Factory>()`, and returns the facade.

The facade (`com.trm.sightline.shared.SightlineShared`) is thin and UI-free:
`categories` (`List<PlaceCategory>`), `nearbyPlaces(category, location, radiusMeters)` (suspend, sorted nearest-first), `authorizationState`, `locationEnabled`, `locationUpdates`, and `preferences` (`PreferencesFacade`: search radius, custom location, user-location enabled get/set flows) for ticket 25.
Facade behavior is covered by `shared/src/commonTest/.../SightlineSharedTest.kt` (4 tests: distance ordering, query forwarding, category list, preference delegation), run on the iOS simulator target with `./gradlew :shared:iosSimulatorArm64Test`.

`iosApp/` is a SwiftUI app generated by XcodeGen 2.48 (`project.yml`, committed `iosApp.xcodeproj`), built as `Sightline.app` under the `com.trm.sightline` bundle id.
Its `Build Shared framework` run script calls `./gradlew :shared:embedAndSignAppleFrameworkForXcode` from the repo root, with `ENABLE_USER_SCRIPT_SANDBOXING: NO` and `FRAMEWORK_SEARCH_PATHS = shared/build/xcode-frameworks/$(CONFIGURATION)/$(SDK_NAME)`; the target links `-framework Shared -framework CoreLocation`.
`Support/Info.plist` carries `NSLocationWhenInUseUsageDescription`.
The single screen has a category picker and a list of nearby places with loading, empty, error, and waiting-for-permission states; it uses only SwiftUI.

`IosLocationProvider` was tightened for the app: it now uses one Core Location delegate, exposes a reactive `authorizationState` backed by `MutableStateFlow`, initializes it from the current status, and requests when-in-use authorization when location updates are first collected.
Android code did not change and no Android bug blocked this ticket.

## Handover notes for 23/24/25

- Keep `shared` iOS-only. Adding an Android target would drag SKIE and the iOS entry point into the Android build.
- The framework is static. Xcode links it with `-framework Shared`; any further Kotlin/Native platform library used from shared code (CoreMotion, Metal, UIKit) may need its system framework added to `OTHER_LDFLAGS` in `project.yml`.
- `project.yml` is the source of truth; regenerate `iosApp.xcodeproj` with `xcodegen generate`. Do not hand-edit the project file.
- The framework build phase runs on every Xcode build (`basedOnDependencyAnalysis: false`) and costs 10-30 s warm; that is intentional so the Swift app never links a stale framework.
- MapLibre for iOS should be added to the `iosApp` target (SPM/CocoaPods through XcodeGen), not to `shared`; the shared layer should expose data, not render views. MapLibre's XCFramework is dynamic and independent of `Shared`.
- Metal work for ticket 24 can live in `iosApp/Sources` as `.metal` files; XcodeGen includes them through the `Sources` folder and Xcode compiles them with the target. Static Kotlin/Native code cannot own Metal shader resources.
- Ticket 25 can extend `SightlineShared.preferences` / add a preferences facade method instead of creating a second Metro graph; the graph factory already accepts the data directory.
- If a new type from `core:domain` or `core:datastore` becomes Swift-visible, add it to `binaries.framework.export(...)` and keep the matching `api(project(...))` dependency in `shared`.
- On a fresh simulator the app prompts for location on first collection; for scripted runs pre-grant with `xcrun simctl privacy <udid> grant location com.trm.sightline` and set a coordinate with `xcrun simctl location <udid> set ...`.
